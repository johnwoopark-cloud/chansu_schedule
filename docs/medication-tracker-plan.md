# 복약 기록 웹앱 기획안

## 1. 목표

- 지금 먹고 있는 약(이름·용량), 복용 시기, 약을 받아 온 날짜를 기록한다.
- 날짜별·복용 시기별로 "먹었음/안 먹음"을 체크한다.
- 정해진 시간이 지나도 체크하지 않았으면 알림을 띄운다.
- **모든 데이터는 내 기기 안에만 저장한다.** 서버, 계정, 클라우드 동기화 없음.

## 2. 개인정보 원칙

| 원칙 | 구현 방법 |
|---|---|
| 데이터는 기기 밖으로 나가지 않는다 | 브라우저 IndexedDB에만 저장. 백엔드 API 없음 |
| 외부 요청 없음 | 폰트·라이브러리·아이콘을 앱에 포함(번들). CDN, 분석 도구, 광고 SDK 사용 안 함 |
| 오프라인 동작 | PWA(Service Worker)로 첫 설치 후 네트워크 없이 실행 |
| 백업은 사용자가 직접 | JSON 파일 내보내기/가져오기. 선택 시 비밀번호로 암호화(WebCrypto AES-GCM) |
| 기기 분실 대비 | 선택 기능: 앱 실행 시 PIN 잠금 |

> 참고: 이 저장소의 기존 `notify.py` + GitHub Actions 방식(서버에서 이메일 발송)은 데이터가 GitHub와 Gmail을 거치므로 복약 정보에는 **쓰지 않는다.**
> 앱 코드 자체는 GitHub Pages 같은 정적 호스팅에 올려도 된다. 코드만 내려받고 데이터는 브라우저에 남기 때문이다.

## 3. 핵심 기능

### 3.1 약 관리
- 약 이름, 1회 용량(숫자 + 단위: 정, mg, mL, 포 등), 제형, 메모(식전/식후, 주의사항)
- 복용 시기: 아침 / 점심 / 저녁 / 취침 전 / 직접 추가(예: "오후 3시")
  - 시기마다 기준 시각을 설정(예: 아침 08:00)
  - 약마다 어떤 시기에 몇 개 먹는지 지정
- 복용 주기: 매일 / 요일 지정 / N일마다 / 필요할 때(PRN)
- 복용 기간: 시작일, 종료일(선택). 종료되면 "복용 중단" 목록으로 옮겨 기록은 보존

### 3.2 약 받아 온 기록(처방·조제)
- 받은 날짜, 병원/약국(선택), 받은 양(일수 또는 개수), 메모
- **남은 양 추정**: 받은 양 − 복용 체크한 양 → "약 N일분 남음"
- 남은 양이 설정값(예: 5일분) 아래로 떨어지면 "약 받으러 갈 때" 알림

### 3.3 복용 체크
- **오늘 화면**: 복용 시기별 카드에 그 시기에 먹을 약 목록 표시
  - 시기 전체 한 번에 체크 또는 약별로 체크
  - 상태: 복용함 / 건너뜀(사유 메모) / 미체크
  - 실제 복용 시각 자동 기록, 수정 가능
- **달력 화면**: 날짜별 달성 상태를 색으로 표시(모두 복용 / 일부 / 미복용)
  - 지난 날짜를 눌러 뒤늦게 체크하거나 수정

### 3.4 알림
3.5에서 자세히 정리한다. 기본 동작:
- 복용 시기 기준 시각 + 유예시간(예: 30분)이 지나도 미체크면 알림
- 알림을 눌러 바로 "복용함" 처리
- 일정 간격으로 다시 알림(최대 횟수 설정)

### 3.5 알림 구현 방식 (가장 중요한 기술 판단)

웹앱은 앱이 닫혀 있을 때 **서버 없이** 정해진 시각에 알림을 보내기가 어렵다.
웹 푸시(Web Push)는 푸시 서버가 필요하고, 예약 알림 API(Notification Triggers)는 표준화가 중단됐다.
"내 기기에서만"을 지키면서 쓸 수 있는 방법은 다음과 같다.

| 방식 | 앱이 닫혀도 동작 | "안 먹었을 때만" 알림 | 서버 | 비고 |
|---|---|---|---|---|
| A. 앱 실행 중 알림(Notification API + 타이머) | ✗ | ○ | 없음 | 탭/앱이 떠 있을 때만 |
| B. 캘린더 내보내기(.ics, 알람 포함) | ○ | ✗(항상 울림) | 없음 | OS 캘린더가 확실히 울려 줌 |
| C. 네이티브 앱으로 감싸기(Capacitor 로컬 알림) | ○ | ○ | 없음 | 체크하면 그 회차 알림을 취소. 가장 확실 |
| D. 직접 운영하는 푸시 서버 | ○ | ○ | 필요 | 개인정보 원칙과 충돌 → 제외 |

**결론**
- 1단계(MVP): **A + B**. 앱을 열면 미복용 시기를 배너로 보여 주고, 열려 있는 동안은 알림을 띄운다. 확실한 정시 알림은 캘린더(.ics)로 받는다.
- 2단계: **C**. 같은 웹 코드를 Capacitor로 Android/iOS 앱으로 감싸서, 기기 안에서 로컬 알림을 예약하고 복용 체크 시 해당 알림을 취소한다. 진짜 "안 먹었을 때만" 알림은 이 방식이 가장 확실하다.

## 4. 화면 구성

1. **오늘** – 복용 시기별 카드, 체크 버튼, 미복용 경고 배너, 남은 약 경고
2. **달력** – 월간 달력, 날짜별 상세, 지난 기록 수정
3. **약** – 복용 중인 약 / 중단한 약 목록, 추가·편집
4. **받아 온 기록** – 날짜별 처방·조제 내역, 약별 남은 양
5. **설정** – 복용 시기와 기준 시각, 알림 유예·재알림, 백업/복원, PIN 잠금, 캘린더 내보내기

## 5. 데이터 모델 (IndexedDB)

```text
medications
  id, name, doseAmount, doseUnit, form, notes,
  frequency { type: daily|weekdays|everyNDays|prn, weekdays?, n? },
  slots [{ slotId, quantity }],
  startDate, endDate?, active, createdAt, updatedAt

slots                        # 복용 시기
  id, label("아침"), time("08:00"), order

refills                      # 약 받아 온 기록
  id, medicationId, receivedDate, quantity, daysSupply?, place?, notes

doseLogs                     # 복용 체크
  id, date("2026-10-22"), slotId, medicationId,
  status: taken|skipped, takenAt?, note?
  # 인덱스: [date], [date+slotId], [medicationId+date]

settings
  graceMinutes, repeatMinutes, maxRepeats,
  lowStockDays, pinHash?, lastBackupAt
```

- "미복용"은 따로 저장하지 않는다. 일정상 먹어야 하는데 `doseLogs`에 기록이 없으면 미복용으로 계산한다.
- 약 정보를 바꿔도 지난 기록이 달라지지 않도록, 복용 체크 시 용량을 `doseLogs`에 같이 저장하는 방안을 검토한다.

## 6. 기술 스택

- **프론트엔드**: Vite + Preact(또는 Svelte) + TypeScript. 가볍고 빌드 결과가 정적 파일이다
- **저장소**: IndexedDB(Dexie.js 래퍼)
- **오프라인/설치**: vite-plugin-pwa(Service Worker, manifest)
- **암호화 백업**: WebCrypto(PBKDF2로 키 생성 → AES-GCM)
- **배포**: 정적 호스팅(GitHub Pages 등) 또는 로컬 파일 서버. 서버 측 코드 없음
- **2단계 네이티브**: Capacitor + `@capacitor/local-notifications`

## 7. 개발 단계

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| 1. MVP | 약 등록, 복용 시기 설정, 오늘 화면 체크, 달력 기록, IndexedDB 저장 | 오프라인으로 일주일 기록 가능 |
| 2. 받아 온 기록 | 처방·조제 기록, 남은 양 계산, 부족 경고 | 남은 일수가 화면에 표시 |
| 3. 알림 v1 | 앱 실행 중 알림, 미복용 배너, .ics 내보내기 | 캘린더 알람이 정시에 울림 |
| 4. 백업·보안 | JSON 내보내기/가져오기, 암호화 백업, PIN 잠금 | 다른 브라우저에서 복원 성공 |
| 5. 알림 v2 | Capacitor로 감싸고 로컬 알림 예약/취소 | 앱을 꺼 둬도 미복용 시에만 알림 |
| 6. 부가 | 복약 순응도 통계(주/월 %), 진료 때 보여 줄 요약 화면/인쇄 | – |

## 8. 위험 요소와 대응

- **브라우저 데이터 삭제**: 캐시 정리나 iOS Safari의 미사용 데이터 정리로 기록이 사라질 수 있다
  → `navigator.storage.persist()`로 영구 저장을 요청하고, 홈 화면에 설치하도록 안내하고, 주기적으로 백업을 알림
- **iOS 제약**: 웹 알림은 홈 화면에 설치한 PWA에서만 되고, 그것도 푸시 서버가 있어야 한다 → iOS는 .ics 또는 2단계 네이티브 앱으로 해결
- **시간대·자정 경계**: 취침 전 약을 자정 넘어 먹는 경우 → 시기별로 "전날로 기록" 허용 시간대 설정
- **의료 정보 정확성**: 앱은 기록 도구일 뿐이며 복용 지시는 처방을 따른다는 안내 문구를 넣는다

## 9. 결정이 필요한 사항

1. 주로 쓸 기기: Android / iPhone / PC 브라우저 → 알림 방식 우선순위가 달라진다
2. 2단계 네이티브 앱(Capacitor)까지 갈지, 웹 + 캘린더 알림으로 충분한지
3. 가족 등 다른 사람 약도 함께 관리할지(사용자 프로필 여러 개)
4. 이 저장소(`chansu_schedule`)에 함께 둘지, 별도 저장소로 분리할지
